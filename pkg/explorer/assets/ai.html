How to read these signals

Declared assistance, not a code detector. We recognize explicit co-author / assistance trailers, generated-with declarations and known agent author identities. A tool name in a regular commit subject is not enough. Each result includes the original marker.

No marker means unidentified. Git cannot establish that someone did not use AI. Markers do not prove that every line in the commit was generated. These figures describe recorded declarations, not productivity or quality.

Every reachable commit, once per SHA. Dates use recorded UTC committer dates. Merges and branch commits are included; a repeated trailer inside one commit counts once. Squashed or copied commits with different SHAs remain distinct Git records. The denominator is all commits by that person in the selected period and path, including commits without markers.

Still represented at the end date. A marked commit counts when at least one included line is still attributed to it on the indexed HEAD history at that date. This is not a line survival percentage. Absence can mean the code was changed, deleted, excluded, or the commit was not yet integrated. Renamed files use their path at that date.

Paths and identities. Domain counts use included text-file changes; a commit can touch several domains. People use the same mailmap and name grouping as the ownership explorer. For agent-authored commits, the Git author is shown; a co-author declaration alone does not verify who operated the agent.
